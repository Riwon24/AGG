# exp_bgaug: 배경 픽셀 증강 + 고정 DINOv2 특징 + 이미지 단위 교차검증

10x 이미지 60장(AGG0 28 / AGG1 14 / AGG2 18)에서 시편 마스크 밖(배경) 픽셀을 무작위로 바꾼 증강 이미지를 만들고, 원본과 증강본에서 고정 DINOv2 ViT-B/14 특징을 뽑아 AGG0/1/2 분류 점수가 어떻게 달라지는지 본다.
**모델은 학습하지 않는다** (DINOv2 고정, 분류기는 평균 특징 위의 로지스틱 회귀/kNN). 증강은 분류기 학습 행을 늘리는 역할만 한다.

이 폴더에는 실험을 다시 돌리는 데 필요한 스크립트와 증강 검증 스크립트(b02)가 있다. 이미지, 마스크, 중간 산출물(`outputs/`), 일부 확인용 스크립트(b02b, b02c, b03c; 아래 6절)는 저장소에 없다.

## 2. 실행 환경과 선행 조건

- GPU 특징 추출(b03)과 교차검증(b04, b04b)은 WSL2(Ubuntu, torch + CUDA, scikit-learn)에서 돌렸다. Windows 의 애플리케이션 제어 정책이 unsigned DLL(torch 등)을 막아서다.
- b00, b01, b05 는 torch 와 scikit-learn 이 필요 없고 numpy, cv2, matplotlib, PyYAML 만 쓴다. 이 세 단계는 Windows 가상환경(전처리용, `opencv-python-headless` 포함)에서 실행했다 (WSL 가상환경에서는 실행해 보지 않았다).
- 가상환경은 `exp`(`model/DL/DINOv2`)의 `setup_env_wsl.sh` 로 `~/agg_exp_venv` 를 만든 뒤 `setup_env_wsl_bgaug.sh` 로 `opencv-python-headless==5.0.0.93` 을 추가한다. 설치 버전은 `requirements_freeze_wsl.txt`.
- **다른 폴더의 파일을 읽는다 (읽기 전용).** 이 저장소 배치와 로컬 배치가 달라서 `config.yaml` 의 `paths` 를 맞춰야 한다.
  - 시편 마스크 `m01_masks/masks/*.png` 와 타일 좌표 `m02_tiles/tiles.csv`: `data/ML_preproc` 의 출력.
  - 이미지 목록 `manifest_v1.csv`(`s00b_meta_mag`)와 10x 원본 이미지: `data/preproc` 의 출력과 이미지 폴더.
  - 기존 실험(`model/DL/DINOv2`) 코드 `common.py`, `e03_run_cv.py`(`bg_common.py` 가 `../exp` 에서 불러옴)와 출력(`e00` 분할, `e01` 출처 해시, `e02` 기준선, `e04` 결과표).
  - DINOv2 공식 저장소와 가중치(`~/.cache/torch/hub`).
- `config.yaml` 의 사용자 이름은 `<USER>` 로 바꿔 두었다. 절대 경로(`C:/Users/<USER>/...`, `/mnt/c/Users/<USER>/...`)는 실제 위치로 바꿔야 한다.

```
# Windows (PowerShell, 전처리용 가상환경의 python)           # 입력 점검, 배경 측정
python b00_check_inputs.py
python b01_measure_background.py
python b02_make_aug_images.py                   # 증강 검증 (약 5분). 선택: b03 은 이 출력을 읽지 않는다

# WSL (이 폴더에서)                                           # GPU 특징 추출, 교차검증, 순열 검사
bash run_wsl.sh b03_extract_features.py        # 약 6~7분 (RTX 3060)
bash run_wsl.sh b04_run_cv.py
bash run_wsl.sh b04b_permutation.py

# Windows                                                     # 보고서와 그림
python b05_report.py
```

모든 스크립트는 시드를 고정했다 (b03 은 같은 입력을 두 번 실행해 특징이 같음을 확인한다). 로그는 `outputs/<스크립트 이름>/log.txt`.

## 3. 설계

### 증강 (`bg_common.augment_image`)
- 이미지 전체에 한 번 적용한 뒤 타일을 자른다 (타일마다 따로 하면 겹치는 타일에서 같은 배경 픽셀이 서로 다른 값이 된다).
- **시편 픽셀은 바꾸지 않는다.** 마스크 안쪽과 마스크 경계에서 8px(`buffer_px`) 이내는 원본 그대로 두고, 그 바깥 16px(`feather_px`) 구간에서 알파로 합성 배경에 섞는다. 스케일바 구역도 마스크 밖이면 합성 배경으로 바뀐다.
- 합성 배경 = 평균색 + 저주파 색 장(σ=40px) + 중간 대역 질감 + 채널 상관을 맞춘 미세 노이즈. 값 세트는 b01 이 측정한 60장 풀에서 무작위로 뽑는다 (라벨 미사용). 시드는 (seed, 이미지 번호, k).
- 블렌딩 구간에서 노이즈 분산이 줄지 않게 분산 보존 블렌딩을 쓴다.
- 이미지당 증강본 K=5 (k=1..5), k=0 은 원본.

### 타일 (config `tiles`)
- 특징 추출(b03)은 `ML_preproc` 의 격자 전체 2,880개(224px, stride 224 로 서로 겹치지 않음, 이미지당 8x6)에 대해 한다.
- 분석(b04 이후)에는 그중 시편 픽셀이 있는 타일을 쓴다 (`select: all_grid`, `drop_zero_mask: true`). 결과 **2,591개**(이미지당 36~48개), 시편 픽셀의 99.74%가 들어간다 (처음 실험의 타일 1,514개는 72.4%).
- 이 타일은 `ML_preproc` 의 이전 stride 112 격자(9,900개)에서 겹치지 않는 부분 격자를 골랐을 때와 **같은 타일**(같은 이미지, x0, y0, mask_px)이고 `tile_id` 만 다르다 (stride 224 격자 번호). 2026-10-24 에 stride 224 격자로 입력을 바꿔 전체를 다시 돌렸다.
- 배경이 섞인 타일(1,282개)은 학습 때 원본과 증강본이 모두 쓰인다. 배경이 완충 띠 안에만 있는 타일은 증강해도 원본과 같다.
- 격자가 이미지 오른쪽 32px, 아래 24px 를 덮지 않아 시편 픽셀의 0.26%는 어떤 타일에도 안 들어간다.

### 분류와 평가 (b04)
- 이미지 벡터 = 버전 k 의 타일 특징을 이미지 안에서 평균 (aggregator mean). 설정 3개: cls · mean · logreg (**primary**), cls+patchmean · mean · logreg, cls · mean · kNN.
- logreg: 표준화(train 에서만 fit) + L2, C=1.0, class_weight=balanced. kNN: k=5, cosine, 거리 가중, 표준화 없음. 구현은 `e03_run_cv.py` 의 `fit_predict_proba` 를 그대로 쓴다.
- 분할은 기존 `e00` 의 이미지 단위 층화 5-fold x 10 반복을 재사용한다. 한 이미지의 모든 버전(원본, 증강본)은 같은 쪽에만 들어간다 (assert).
- 팔 4개:
  - R0: 원본 학습 → 원본 평가 (증강 없음)
  - **R1 (primary 팔)**: 원본+증강본 학습 → 원본 평가
  - R2: 원본+증강본 학습 → 증강본 평가
  - R3: 원본 학습 → 증강본 평가
  R2, R3 은 증강본 5개의 확률을 평균한 값이라 R0, R1 과 직접 비교하지 않는다.
- primary 설정과 팔은 결과를 보기 전에 정했고 바꾸지 않았다.

## 4. 결과 (이미지 단위 95% CI, 반복 10회 평균 accuracy)

| 설정 | R0 | **R1 (primary 팔)** | R2 | R3 |
|---|---|---|---|---|
| cls · mean · logreg (primary) | 0.813 [0.728, 0.892] | **0.827** [0.748, 0.898] | 0.852 | 0.778 |
| cls+patchmean · mean · logreg | 0.803 | 0.827 | 0.840 | 0.788 |
| cls · mean · kNN | 0.758 | 0.800 | 0.875 | 0.745 |

- 기준선: 항상 다수 클래스 0.467, 처리 조건의 다수 라벨 암기 0.90.
- 라벨 순열 20회(primary, R1): accuracy 평균 0.352 (범위 0.27~0.48), 제안 기준 통과.
- **사전 지정한 규칙의 적용 (primary 설정)**
  - 규칙 1: R0−R3 = +0.035, 이미지 단위 CI [−0.027, +0.103]이 0을 포함 → 원본 학습 모델이 배경에 기대고 있었다고 단정하지 않는다.
  - 규칙 2: R1−R0 = +0.013, CI [−0.027, +0.058]이 0을 포함 → 증강 효과가 있다고도 없다고도 단정하지 않는다.
  - 처리 조건 단위 CI 도 두 비교 모두 0을 포함한다. 다른 두 설정도 같다.
- 탐색(사전 지정 아님): R2−R3 = +0.073, CI [+0.005, +0.152] (조건 단위 CI 는 0을 포함).
- 이전 실험(`model/DL/DINOv2`, 겹치지 않는 타일 1,514개, 증강 없음)의 primary 0.712 에서 R0 가 0.813 으로 오른 것은 타일 집합이 바뀐 영향이고 증강 때문이 아니다 (R0 에는 증강이 없다).
- R3 에서 AGG1 재현율이 0.60 → 0.31, AGG0 가 0.89 → 0.98 로 변했다 (배경을 바꾸면 예측이 AGG0 쪽으로 쏠린다). 원인은 이 실험으로 가르지 않았다.

## 5. 결정 이력

| 단계 | 결정 / 시도 | 이유 |
|---|---|---|
| 링 | 완충 띠 바깥을 바로 교체(feather 0px)하지 않고 16px 구간에서 블렌딩 | 거리별 평균 프로파일(노이즈를 평균으로 지움)에서 밝기 급변 z>3 이 feather 0px 70%, 16px 6% |
| 노이즈 | 채널 독립 노이즈를 측정한 채널 공분산(상관 0.96~0.98)으로 교체, 분산 보존 블렌딩 | 처음 만든 합성 배경의 미세 노이즈가 원본의 약 55%여서 노이즈 크기의 경계가 생겼음 |
| 타일 | m02 의 마스크 비율 >= 0.5 선택(7,921개) → 격자 전체(9,900개) → 겹치지 않는 부분 격자 + 시편 0 제외(2,591개) → m02 를 stride 224 로 바꿔 격자 2,880개에서 시편 0 제외(같은 2,591개) | 사용자 결정, 모두 b04 결과를 보기 전 |
| 색 범위 | 증강 색 범위는 60장 배경 측정 풀에서 라벨 없이 뽑는다 | 사람이 손으로 값을 정하지 않음 |

## 6. 검증 요약과 저장소에 없는 확인용 스크립트

- `b02` (저장소에 있음): 모든 이미지, 증강본, feather 후보에서 마스크 안쪽과 완충 띠 이내 픽셀이 원본과 uint8 로 완전히 같음 (300x2개 전부), 같은 시드로 다시 만들면 sha256 이 같음.
- 링(증강에만 생기는 두 번째 경계) 점검: 처음 쓴 기울기 지표(`ring_ratio`, b02)는 노이즈 기울기에 묻혀 링을 못 잡았다. 노이즈를 평균으로 지운 거리별 평균 프로파일(`b02c`, 저장소에 없음)에서 밝기 급변 z>3 이 feather 0px 209/300 (70%), 16px 19/300 (6%).
- 저장소에 없는 확인용 스크립트 (로컬에만 있음, 실험 재현에는 필요 없음): `b02b` (60장 마스크/증강 확인 시트), `b02c` (링 점검, 위), `b03c` (학습 타일 배치 그림).
- `config.yaml` 의 `feather_candidates_px`, `ring_ratio_threshold` 는 b02 가, `ring_z_threshold` 는 저장소에 없는 `b02c` 만 쓴다 (실험 스크립트는 `feather_px` 를 쓴다).

## 7. 한계

1. **처리 조건 혼동**: 라벨의 90% 정도가 처리 조건으로 설명된다 (처리 조건 암기 0.90). 같은 처리 조건의 이미지가 train 과 test 에 모두 있어서 점수가 형태를 읽은 결과인지 처리 조건을 알아본 결과인지 구분되지 않는다. 처리 조건 단위 분할 평가는 하지 않았다.
2. **모델은 학습하지 않았다**: 모델 자체를 개선했다고 말할 수 없다.
3. **합성 배경의 한계**: 노이즈의 공간 상관과 중간 대역 질감(원본의 약 0.84배, 이미지별 편차 큼)은 완전히 맞추지 않았다.
4. **마스크 한계**: `m01` 마스크가 시편 일부를 놓친 이미지(예: BASE-LCSI/NPH1035 오른쪽 위)에서는 그 부분의 시편 픽셀이 배경으로 취급되어 증강될 수 있다. 완충 띠 8px 가 일부만 막는다. 이미지별 수동 보정은 하지 않았다.
5. 표본이 이미지 60장이라 CI 가 넓다. 반복 10회의 SD 는 같은 이미지를 다른 분할로 본 변동이다. 이미지 단위 CI 는 이미지를 독립으로 보기 때문에 같은 처리 조건 안의 상관을 반영하지 못한다 (처리 조건 단위 CI 가 더 보수적이다).

## 8. 용어

- 1단계 폴더(`BASE`, `BASE-LC`, `BASE-LCSI`, `BASE-LSi`, `REF`, `REF-LN`) = **금속 종류**.
- 2단계 폴더(`NPH1035`, `PH1180-1050` …) = **처리 조건** = 처리 방법(NPH, PH1180, PH1205, PH1230, PH1255) x 온도(1035, 1050).
- `image_id` = `금속/처리 조건/파일명(확장자 제외)`.
