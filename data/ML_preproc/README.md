# ML_preproc

딥러닝용 데이터 준비: **시편 마스크(m01) → 타일 좌표(m02)**. 10x 이미지 60장(1824×1368, 라벨 AGG0/1/2)만 대상이다.
기존 `../preproc`(s00~s07)의 출력을 읽기 전용으로 가져와 쓰고, 여기서는 마스크와 타일만 새로 만든다.

> 폴더 이름은 `ML_preproc`지만 수작업 특징을 쓰는 머신러닝은 폐기했다(아래 5절). 지금은 딥러닝 입력 준비용이다.

## 1. 한눈에 보기

| 단계 | 스크립트 | 하는 일 | 주요 출력 |
|---|---|---|---|
| m01 | `m01_masks.py` | 시편 마스크 60장 | `outputs/m01_masks/masks/*.png`, `selection.csv`, `check_01~10.png` |
| m02 | `m02_tiles.py` | 224px 타일 좌표 (stride 224, 겹침 없음) + 마스크 비율, 선택 | `outputs/m02_tiles_s224/tiles.csv`, `tile_counts.csv`, `qc_grid_AGG*.png` |

- 파라미터는 모두 `config.yaml`에 있다 (하드코딩 금지). `outputs/`는 `.gitignore` 대상이라 저장소에 없다.
- 원본 이미지는 읽기만 한다. 배경을 지우거나 칠하지 않는다.
- 같은 입력이면 같은 출력이 나온다 (`tiles.csv` sha256 확인).

## 3. m01 — 시편 마스크

출발점은 `../preproc`의 `otsu_v`(명도 Otsu)다. 여기에 "파랗지 않거나 파란 핵심부에서 멀면 감점"하는 점수를 얹는다.

```
점수 = A + lambda_blue*(B-1) + lambda_prox*(P-1)      점수 > 0 이 시편
A = tanh((V - Otsu 임계값) / sigma_v)                  밝기 (otsu_v 와 같은 방향)
B = exp(-(H-H0)^2 / 2 sigma_h^2) x 채도 문             파랑 (H0 = 핵심부 색상 중앙값)
P = exp(-max(d - d0, 0) / tau)                         핵심부(hue_sv)까지 거리 d 에 대한 근접
```

- **감점 전용**: B, P가 0~1이라 점수는 A보다 커질 수 없다. 마스크는 `otsu_v`가 시편으로 본 영역 안쪽에서만 줄어든다.
  (대칭 `2x-1`로 두면 보너스 때문에 마스크가 사방으로 부풀었다.)
- 그 뒤 최대 연결 영역 하나만 남기고 구멍을 메운다.
- **이미지별 변형 선택** (모든 이미지에 같은 규칙, 수동 보정 없음):
  `otsu_v` 마스크 안쪽 V(명도) 중앙값 ≥ 135 → **plateau**(핵심부에서 d0=50px까지 근접 감점 없음, 밝고 파란기 약한 시편의 흰 띠 보존), 미만 → **baseline**(d0=0).
  근거: 두 변형이 크게 다른 7장에서 어두운 쪽 V 중앙값이 104, 116, 밝은 쪽이 152 이상이고 117~151 구간에는 이미지가 없었다.
- 결과: plateau 39장 / baseline 21장, `otsu_v` 대비 IoU 중앙값 0.998 (0.99 미만 4장), 스케일바 구역과 겹치는 마스크 0장.

## 4. m02 — 타일 좌표

- 224px 타일, **stride 224px(겹침 없음)**, 격자는 (0,0)에서 시작한다. 이미지당 8×6 = 48개, 오른쪽 32px와 아래 24px는 쓰지 않는다.
- 타일 안에 시편(마스크) 픽셀이 **1개 이상**이면 선택한다 (`min_mask_frac: 0`; 0보다 큰 값을 주면 마스크 비율 ≥ 그 값). 침식 마진은 쓰지 않는다.
- 스케일바 제외 구역 [1670, 1277, 1824, 1368] 픽셀은 마스크에서 뺀다 (m01 마스크는 이미 겹치지 않는다).
- 패치 라벨은 없다. `label` 열은 이미지 라벨(0/1/2)을 복사한 것이다.
- 출력 폴더는 `config.yaml`의 `tiling.out_name`(`m02_tiles_s224`)이다.

`tiles.csv` 열: `image_id, label, tile_id, x0, y0, w, h, mask_frac, selected, overlaps_scalebar, mask_px` (타일 한 개가 한 행, 이미지 60장 × 48 = 2,880행). **쓸 타일은 `selected == 1`.**

| 항목 | 값 |
|---|---|
| 선택 타일 | 2,591개 (90.0%), 이미지당 36~48 (중앙값 44) |
| 클래스별 | AGG0 1,216 / AGG1 590 / AGG2 785 |
| 마스크 100%인 선택 타일 | 1,309개 |
| 일부만 마스크인 선택 타일 | 1,282개 (49.5%; 마스크 비율 0.75 미만 557개, 0.75~1.0 미만 725개) |
| 스케일바 구역과 겹치는 선택 타일 | 36개 (해당 픽셀은 마스크 밖) |
| 선택되지 않은 타일 | 289개 (모두 시편 픽셀 0) |
| `tiles.csv` sha256 | `c645ee4f9630…` |

**이전 설계(stride 112)와의 관계**
- 이전에는 stride 112px(50% 겹침, 이미지당 165개 = 9,900행)에서 마스크 비율 ≥ 0.5인 7,921개를 선택했고, 분석에서는 그 격자에서 겹치지 않는 부분 격자만 다시 골라 썼다 (60장 모두 (0,0)에서 시작하는 stride 224 격자가 뽑혔다). 이 부분 격자가 바로 지금의 stride 224 격자라서 격자 자체를 바꿨다 (2026-10-24, 사용자 결정).
- 지금의 선택 타일 2,591개는 그 분석 타일(시편 픽셀 0인 타일 제외)과 **(이미지, x0, y0) 좌표, `mask_px`, `mask_frac`이 모두 같다** (좌표 집합 비교로 확인, 확인 스크립트는 저장소에 없음).
- **`tile_id`가 달라졌다.** 이전의 `r행_c열`은 stride 112 격자 번호, 지금은 stride 224 격자 번호다 (같은 타일이 이전 `r00_c02`, 지금 `r00_c01`). 이전 결과(특징 파일 등)와 연결할 때는 `tile_id`가 아니라 `(x0, y0)`로 대응해야 한다.
- stride 112 결과(`outputs/m02_tiles/`)는 이전 실험의 입력이라 지우지 않고 그대로 두었다 (저장소에는 없음).

## 5. 시도했다가 폐기한 것

| 영역 | 시도 | 이유 |
|---|---|---|
| 마스크 | `hue_sv`, 하이브리드(핵심부 팽창), 색도 필터, 줄 단위 가장자리 탐색, 형태 기반 열기 | 흰 띠를 자르거나, 밝은 배경을 못 거르거나, 일부 이미지에서 악화. 색(b*)만으로는 흰 띠와 밝은 배경이 약하게 구분되고, 밝고 파란기 약한 시편에서 b*가 불안정했다 |
| 라벨 없는 이미지 | 같은 로직으로 검증 | 1600×1200 이미지는 시편이 회갈색이라 파란 핵심부가 없어 마스크가 무너졌다 (2장 실패, 9장 IoU<0.75). 1824×1368만 쓰기로 하고 해당 모드는 삭제했다 |
| 특징 | Canny 엣지 밀도 + FFT 8대역 | 처리 조건을 고정하면 엣지 밀도의 라벨 설명력이 1%, FFT 중간 대역 10~13%. 고주파 대역(b5~b7)은 센서 노이즈 바닥에 가까웠다 |
| 특징 | FFT 대역통과 + 질감 에너지 지도, 국소 스펙트럼 모양 이상도 | 편평 영역 후보 0px, 이상 창 비율이 클래스 간 차이 없음(AGG0 0.0007 / AGG1 0.0008 / AGG2 0.0005), 잡힌 것은 모서리와 스크래치뿐. 정답 위치가 없어 검증도 못 했다 |

목표는 "미세 질감이 이어지다가 갑자기 편평해지는 곳"을 찾는 것인데, 이 영역이 매우 미세하고 영역 라벨이 거의 없어서 수작업 특징을 검증할 기준이 없었다. 코드는 저장소에 남기지 않았다.

## 6. 알려진 한계와 주의

- **라벨과 처리 조건이 얽혀 있다.** 처리 조건(2단계 폴더)의 다수 라벨로 라벨을 맞히면 90% (DL 단계의 "처리 조건 암기 기준선"). 어떤 모델이든 AGG를 보는지 처리 조건을 보는지 구분해서 평가해야 한다.
- 같은 이미지에서 나온 타일끼리는 비슷하고 50% 겹친다. **분할은 이미지 단위**로 한다.
- 선택 타일의 49.5%(1,282개)는 마스크를 일부만 포함한다. 마스크 밖 픽셀을 모델 입력에서 어떻게 다룰지(그대로, 평균색으로 채움, 마스크 채널 추가 등)는 모델 설계에서 정한다.
- 마스크가 프레임에 닿는 이미지가 `otsu_v` 36장에서 새 마스크 25장으로 줄었다 (11장이 프레임에서 8~30px 떨어짐, 원인 미확인).
- 그림자 구석(BASE-LCSI/NPH1035 오른쪽 위처럼 `otsu_v`가 놓친 영역)은 감점 전용이라 되살리지 못한다.
- 파라미터(`tau_px`, `lambda_*`, `d0`, 기준값 135)는 9장 안팎을 보고 정했다. 나머지 이미지에는 "`otsu_v`에서 거의 안 바뀐다"는 확인만 있고 "맞다"는 확인은 아니다.
- m01은 `../preproc`의 `s02` 마스크와 `mask_stats.csv`에 의존한다 (V 중앙값을 그 마스크 안쪽에서 계산).

## 7. 용어 (`../preproc/README.md`와 같다)

- 1단계 폴더(`BASE`, `BASE-LC`, `BASE-LCSI`, `BASE-LSi`, `REF`, `REF-LN`) = **금속 종류**, 코드 열 이름은 `treatment`.
- 2단계 폴더(`NPH1035`, `PH1180-1050` …) = **처리 조건** = 처리 방법(NPH, PH1180, PH1205, PH1230, PH1255) × 온도(1035, 1050), 코드 열 이름은 `sample`.
- `image_id` = `금속/처리 조건/파일명(확장자 제외)`.
