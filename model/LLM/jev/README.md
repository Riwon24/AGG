# LLM(JEVision 0.8B) zero-shot AGG0/1/2 분류 실험

> **이 저장소 사본에 대한 안내**: 이미지 파일(원본 사진, `tile_review/`의 타일 확인 시트 4장)은 올리지 않았다. 5절의 시트는 `scripts/review_tiles.py`로 다시 만들 수 있다(원본 이미지와 `preproc` 산출물 필요). 문서 안의 `../preproc/`, `../exp/` 경로와 스크립트 안의 데이터 경로는 원본 작업 폴더(`AGG_labeled_only`) 기준이다.

`AGG_labeled_only`의 이미지를 사전학습된 비전 LLM(JEVision)에 **학습 없이(zero-shot)** 넣어 AGG0/1/2를 분류할 수 있는지 본 테스트.
(DINOv2 특징 + 분류기 실험은 `../exp/README.md`, 전처리는 `../preproc/README.md`. 이 폴더는 그와 독립된 LLM 실험이다.)

## 1. 한 줄 요약

| 방식 | 평가 대상 | accuracy | macro-F1 | 비고 |
|---|---|---|---|---|
| 전체 사진 + 프롬프트 v1 | 179장 | 0.464 | 0.269 | 거의 전부 AGG0으로 예측 |
| 전체 사진 + 프롬프트 v2 | 179장 | 0.257 | 0.177 | 거의 전부 AGG1로 예측 |
| **타일(224px) 점수 → 이미지 평균** | 10x 60장 | 0.733 (※) | 0.689 (※) | AUROC AGG2 vs AGG0 0.944. ※임계값을 같은 데이터에서 골라 **낙관적인 상한** |
| 기준선 (항상 다수 클래스) | 179장 / 10x 60장 | 0.464 / 0.467 | - | |

- 전체 사진을 한 번에 넣으면 모델이 이미지에 반응하지 않았다(프롬프트를 바꾸면 기본 답만 바뀜).
- 224px 타일로 쪼개 타일별 점수를 이미지 단위로 평균하면 **AGG2를 가려내는 신호**가 생겼다. 다만 AGG1 구분은 약하고(AUROC 0.66), 타일 점수에는 조명 띠·스크래치·이물질 같은 아티팩트 오탐이 섞여 있다(5절).
- 라벨이 처리 조건과 강하게 얽혀 있어(`../preproc/README.md` 7절), 타일 점수가 AGG를 본 것인지 처리 조건의 외형을 본 것인지는 **분리하지 못했다**.

## 2. 설정

### 모델·환경
- 모델: [divyanshx11/JEVision](https://huggingface.co/divyanshx11/JEVision) (Qwen3.5-0.8B-Base + 어댑터, Apache-2.0, 교수님 추천). 선택지(`choice`/`noul`) 확률을 출력한다. 모델 카드에도 이 확률은 보정된 값이 아니라고 되어 있다. 출력 확률은 소수 둘째 자리로 반올림되어 나온다.
- 어댑터 파일 12개는 저장소의 `jevvision_manifest.json` SHA256과 모두 일치함을 확인했다. 게시자는 개인 계정 하나이며 독립 검증은 없다. 성능 수치는 모델 카드 자체 보고다.
- 실행: WSL2 Ubuntu, RTX 3060 12GB, Python 3.14, 버전은 `results/env_versions.txt`. 이미지 한 장당 약 1초(타일은 더 빠름).
- **환경 차이(주의)**: WSL에 C 컴파일러·sudo가 없어 triton을 쓸 수 없다. `flash-linear-attention`을 설치하지 않고 `TORCH_DISABLE_NATIVE_JIT=1`로 실행해 transformers의 순수 PyTorch 대체 경로로 돌렸다. 모델 카드의 테스트 환경(T4, 최적화 커널)과 수치가 미세하게 다를 수 있다.
- 입력 해상도: 전체 사진 1824x1368은 모델 입력에서 1824x1376(비전 토큰 약 2,451개)으로 사실상 원본 그대로다. 224px 타일은 프로세서의 최소 픽셀 수 때문에 약 256x256으로 확대되어 들어갈 수 있다(확대 크기는 확인하지 않음).

### 데이터
- `AGG_labeled_only` 이미지 179장(전부 1824x1368 JPEG). 라벨: AGG0 83 / AGG1 43 / AGG2 53.
- 타일: `../preproc/outputs/s04_tile_grid/tiles.csv`의 `selected == 1` 1,514개(10x 60장, 224x224, 서로 겹치지 않음, 시편 마스크 안쪽만).
- 파일명 오타(`x101`, `x12.54`, `x7.51`, `X7.5` 등)는 배율을 접두어 정규식 `[xX](12\.5|10|7\.5)`로 정규화해 집계에 사용했다. 이미지 파일명은 바꾸지 않았다. (전체 사진 평가의 배율별 집계는 이 정규식 기준이며, 10x 부분집합은 `preproc`의 배율 확정(xlif 기준)과 일부 다를 수 있다.)

### 프롬프트
- **v1** (전체 사진): "microscope image of a metal sample after heat treatment, decide whether AGG occurred", 선택지 AGG0 = 정상 / AGG1 = 부분적 AGG / AGG2 = 심한 AGG (한 줄 정의).
- **v2** (전체 사진): 사용자 정의("이상 결정립 성장 = 주변 질감과 다르게 편평한 부분")를 반영. 저배율 시편 표면 사진임을 알려 주고, 정상 = 균일한 미세 알갱이, AGG = 주변 질감과 다른 편평하고 매끈한 영역, 배경과 시편 가장자리는 무시하라고 지시. (이 "배경·가장자리 무시"는 사용자 정의가 아니라 추가한 문구.)
- **타일** (`scripts/run_tiles.py`의 `STATE`/`QUESTIONS`): 약 2 mm 크기 시편 표면 조각이라고 설명하고 두 가지를 묻는다.
  - `flat`(예/아니오): "주변의 미세 질감과 다른 편평하고 매끈한 영역이 있는가?" → 확률 `p_flat`
  - `extent`(NONE/PARTIAL/MOST): 편평한 영역이 얼마나 차지하는가 → **쓸모 없음**(5절)

타일마다 `p_flat`을 구하고, 이미지별로 평균(`mean_flat`)하거나 `p_flat > 0.5` 타일의 비율(`frac_flat`)을 구했다.

## 6. 한계와 주의

- **라벨과 처리 조건의 얽힘**: 처리 조건으로 라벨을 맞히면 54/60 = 90%(`../preproc/README.md` 7절). 모델 점수가 처리 조건의 외형(조명·색)을 반영하는지 분리하지 못했다. 촬영 구도도 조건별로 달랐다(NPH는 시편이 프레임을 가득 채움, PH는 가장자리·배경이 보임).
- **평가 범위**: 타일 방식은 10x 60장뿐이다(타일이 10x에만 만들어져 있음). 7.5x/12.5x는 하지 않았다. 표본이 작아(AGG1 14장) 지표의 분산이 크다.
- **임계값 낙관**: 타일 3분류 수치는 임계값을 평가 데이터에서 골랐다. 교차검증이나 별도 분할을 하지 않았다.
- **확률의 한계**: 모델 확률은 보정되지 않았고 둘째 자리로 반올림되어 동점이 생길 수 있다.
- **프롬프트 탐색 범위**: 전체 사진 v1, v2와 타일 v1만 시도했다. few-shot, 아티팩트 무시 지시, 조명 보정, 다른 모델(Claude API 등)은 하지 않았다.
- 재현성: 같은 입력에서 같은 출력이 나오는지(두 번 실행 비교)는 확인하지 않았다.

## 7. 재현 방법

WSL2 Ubuntu 기준(스크립트 경로·모델 폴더는 `~/jevision_work/`를 가정; 필요하면 스크립트 상단의 경로를 고친다).

```bash
git clone https://huggingface.co/divyanshx11/JEVision ~/jevision_work/JEVision   # LFS 파일은 huggingface_hub로 받고 manifest의 SHA256과 대조
export TORCH_DISABLE_NATIVE_JIT=1                       # WSL에 C 컴파일러가 없을 때(flash-linear-attention 미설치)
python scripts/run_agg.py --prompt v1                   # 전체 사진 179장 -> results/zeroshot_v1.jsonl (v2도 동일)
python ../eval_agg.py results/zeroshot_v1.jsonl    # 혼동행렬, 클래스별 지표, 배율·금속·조건별 정확도
python scripts/run_tiles.py                             # 선택 타일 1,514개 -> results/tiles_v1.jsonl
python scripts/agg_tiles.py results/tiles_v1.jsonl      # 이미지 단위 집계, AUROC, 임계값 3분류, 10x 비교
python scripts/review_tiles.py                          # tile_review/ 시트 생성
```
